§01 · Problem Statement

Why Enterprise Workspace RAG Leaks Restricted Data & Fails Across Modalities

Why bolting dense vector search onto corporate spreadsheets, BI dashboards, call transcripts, and RFCs breaks enterprise security and retrieval accuracy—and how QuickSpaces solves all three failure modes.

Amazon Quick Suite Inspired Architecture

IN PLAIN ENGLISH What QuickSpaces Does & Why Standard Enterprise AI Chatbots Leak Secrets

Imagine a company team folder ("Space") that holds four completely different kinds of files about Q3 cloud revenue: a finance spreadsheet full of customer ARR numbers and social security / API key columns, an executive BI dashboard, a 45-minute recorded customer escalation call, and an engineering RFC document. When a VP asks "Why did EMEA revenue drop in Q3 and when does the fix ship?", they want one grounded answer that pulls the exact dollar drop from the spreadsheet, the regional trend from the BI chart, and the November 18 ship date spoken at [08:45] on the call.

Most RAG systems dump every document chunk into one vector index, fetch the top matches first, and check permissions second. That breaks in two ways: an external contractor can trigger side-channel leaks or receive empty answers because restricted chunks hogged the top slots, and long call transcripts drown out compact CSV tables. QuickSpaces checks who you are, which region you sit in, and which spreadsheet columns contain PII before scoring a single chunk—then fuses keyword + semantic search across all four file types and audits Space security settings automatically.

🎯 Enterprise Workspace Problem Space: Built for multi-tenant collaborative AI workspaces (modeled on Amazon Quick / Quick Suite) where executives, regional analysts, and external contractors collaborate over mixed tabular, BI, conversational, and technical assets under strict GDPR/KMS & PII compliance.
10 Eval Queries · 5 Adversarial Probes · 3 Spaces
PROBLEM 01 · POST-RETRIEVAL ACL LEAKS

Post-Retrieval Filtering Leaks & Starves Context

Standard RAG retrieves global top-K vector chunks first and filters permissions afterward. When confidential EMEA escalation transcripts dominate top-K, unauthorized callers suffer empty top-K starvation—or worse, unmasked PII columns (signatory_ssn, cfo_contact_phone, connector_api_key) leak into LLM prompt assembly.

🛑 Security Gap: 5 adversarial contractor & regional clearance probes target restricted assets
PROBLEM 02 · CHUNK-ONLY BIAS ACROSS MODALITIES

Long Transcripts Crowd Out Tabular & BI Rollups

Splitting CSV cohorts, BI KPI cards, 45-minute .vtt call recordings, and Markdown RFCs into uniform text chunks lets verbose transcripts flood top-3 slots while structured numeric rollups (sum, avg, cohort deltas) miss retrieval—limiting chunk-only ranking to 80.0% top-3 asset recall.

📉 Retrieval Gap: 80.0% chunk-only Top-3 asset recall without RRF + Asset Max-Pooling
PROBLEM 03 · MANUAL WORKSPACE GOVERNANCE DRIFT

Unmasked PII, Guest Links & Missing EU KMS Pins

Teams continuously upload ad-hoc CSVs and call recordings into shared Spaces without enabling column-level PII masking, revoking external contractor share links, pinning EMEA confidential shards to eu-central-1 KMS CMKs, or attaching retention:90d S3 Object Lock tags.

⚠ Governance Drift: 59.7 / 100 average initial readiness across the 3 enterprise Spaces

§03 · Implementation

Core Python Modules, Parsers & Security Controls

Every ingestion parser, pre-retrieval ACL predicate, Reciprocal Rank Fusion scorer, citation span verifier, and SHA-256 governance receipt chain in quickspaces/ is implemented from scratch in pure Python.

PLAIN-ENGLISH INTUITION

Why Four Specialized Parsers + Asset Max-Pooling Beat Generic Text Splitting

If you chop a CSV spreadsheet into 500-character text blobs, the AI loses column headers and cannot sum or average a column reliably. Worse, a 40-turn meeting transcript creates 40 chunks while a KPI summary creates 2—so transcript chunks monopolize search results. QuickSpaces parses each file type into its native structure first (table rollups, KPI series, [MM:SS] turns, § sections) and scores each parent file by its strongest matching chunk so every modality gets a fair seat in prompt assembly.

UNDER THE HOOD · EXACT CODE, MATH & DATA STRUCTURES

Reciprocal Rank Fusion (k=60), Regex/Header PII Predicates & SHA-256 Chaining

In quickspaces/hybrid_retrieval.py, ACL-cleared chunks are scored by Okapi BM25 (k1=1.5, b=0.75) and L2-normalized character 3-gram TF vectors, then fused via RRF(c) = 1/(60 + rank_bm25(c)) + 1/(60 + rank_cos(c)) and aggregated per asset via score(A) = max_{c ∈ A} RRF(c) (0.67 ms p50 / 1.15 ms p95). Governance receipts chain canonical sorted JSON via SHA256(prev_hash || canonical_payload).

MODULE 01 · MULTI-MODAL INGEST & PII quickspaces/multimodal_ingest.py · models.py

4-Modality Structured Parser & Dynamic Column-Level PII Scanner

  • CSV / Tabular Schema & Rollup Engine: Infers numeric columns, pre-computes exact sum, avg, min, and max cohort rollups, and flags PII columns (SSN, API_KEY, email, phone) at ingestion time.
  • Dynamic Viewer Redaction: Applies role-aware cell masking ([REDACTED:SSN], [REDACTED:API_KEY], masked email/phone) for non-admin principals without mutating raw admin lineage.
  • WebVTT, QuickBI & RFC Chunkers: Preserves [MM:SS] speaker attribution on .vtt calls, SQL warehouse lineage + KPI deltas on .quickbi dashboards, and §2.1 section locators on .md RFCs.

Zero-Leakage Pre-Retrieval ACL Gate + BM25/Cosine RRF + Asset MaxPool

§04 · Design Trade-Offs

Pre-Retrieval Governance & Asset Max-Pooling vs. Standard RAG

Engineering tradeoffs comparing post-filtered dense vector stores against pre-scoring access predicates, modality-aware rollup indexing, and automated policy remediation.

PLAIN-ENGLISH INTUITION

Why Filtering Before Search Prevents Both Leaks and "Empty Answers"

Think of a contractor searching for public pricing inside a folder that also holds 50 confidential board memos. If the search engine grabs the top 5 matches first and then deletes the ones the contractor isn't allowed to see, all 5 slots might be confidential memos—leaving 0 results even though the public pricing sheet was sitting right there at #6! Filtering permissions first guarantees zero data leaks AND complete answers from everything you are authorized to read.

UNDER THE HOOD · EXACT CODE, MATH & DATA STRUCTURES

CLEARANCE_RANK Lattice + Regional Set Intersection + Dynamic Cell Masking

can_access_asset(role, asset) evaluates CLEARANCE_RANK[role.clearance] >= CLEARANCE_RANK[asset.classification] and bool(set(role.regions) & set(asset.regions)) in O(1) per asset before building the posting list. For INTERNAL analysts viewing spreadsheets with flagged PII columns, cell values are transformed at serialization time without duplicating underlying rows.

PRINCIPLE 01 · ZERO-LEAKAGE RETRIEVAL

Access Control Must Run Before Candidate Scoring, Never After

Pushing tenant, regional residency (NA/EMEA), and clearance predicates into the retrieval pre-filter guarantees both 100.0% adversarial block rate (5/5 probes) and zero top-K starvation for lower-clearance roles querying PUBLIC or INTERNAL assets.

PRINCIPLE 02 · MODALITY-AWARE RANKING

Preserve Native Structure & Pool Chunk Scores at the Asset Boundary

Pre-computing CSV numeric rollups, preserving [MM:SS] speaker turns, and max-pooling BM25 + cosine RRF chunk scores per asset prevents multi-chunk call transcripts from drowning out high-signal spreadsheets (80.0% → 90.0% Top-3 recall in 0.67 ms p50).

PRINCIPLE 03 · CONTINUOUS POLICY REMEDIATION

Pair Self-Service Ingestion with Autonomous Governance Guardrails

Enterprise users upload sensitive files daily. Scanning PII columns at ingest time and running a 5-rule autonomous remediation agent (59.7 → 100 mean readiness across 3 Spaces) turns compliance from a multi-week manual review into a 1-click SHA-256 audited operation.
